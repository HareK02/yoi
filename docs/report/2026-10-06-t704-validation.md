## Implemented contracts

- Caller-selected existing Builtin/project registry Profiles, normal virtual
  config/prompt bundle resolution and explicit execution-requirement rejection.
  Chosen instructions/features/model are not replaced with backend-job defaults.
- Immutable Host-authored Job/attempt create/restore binding and result capability,
  independent of Profile names/instructions/tags. No inherited Workdir, parent or
  subject-body execution authority.
- Common transactional resource serialization (Workspace schema 81), immutable
  Subject/candidate batch grants, exact replay vs resource collision, unknown
  fences and all-old-attempt cleanup fences before retry/followup.
- subjektiv requests its Profile; immutable bounded batches, empty surface-only
  Jobs, candidate authorization, existing CAS/atomic receipts and dispositions.
- Synchronous bounded clean-context surface generation before result submission.
  Preparation reports an already-current snapshot to avoid needless conflicting
  regeneration. Job failure acknowledgements are `failed_confirmed` only after
  checking the actual failed marker/reason/revision and generation provenance.
  Subject feature migration 6 adds immutable generation Job/attempt provenance,
  without changing Subject/Memory/candidate content.
- Durable results contain actual candidate dispositions and a separate verified
  ready/failed surface outcome. Existing terminal cleanup retains results/memory.
- Removed subject direct spawn and Idle resubmission. Persisted legacy ownership
  plus actual foreground WorkerState and confirmed stop/removal fence the cutover.
  Busy legacy workers are not interrupted or duplicated; subject bodies and the
  independent old Workspace Memory feature are not selected for removal.

## Bounded-result follow-up after interrupted review

The first implementation was published as `d12cdc91`. Human interruption ended
its first pending Reviewer before a verdict. On retry, the parent reread Ticket,
MR, clean Workdir and provider source. Before the replacement Reviewer verdict,
parent inspection identified a concrete result-budget defect: copying full
resolution records for a 100-ID batch could exceed the common 16 KiB result bound,
even when candidate decisions and surface generation had actually completed.
That pending old-source review was stopped rather than treated as approval.

The follow-up keeps full immutable receipts/reasons/revision/source edges in their
existing store and persists only verified `{candidate_id, action}` summaries in
the Job result. Batch selection conservatively budgets the complete result,
including JSON-escaped IDs in both claim and outcome, plus a reserved bounded
Subject/surface envelope. Candidates beyond that byte-bound stay staged. The
common result bound is not enlarged or bypassed.

A new narrow fixture closes a batch of long/escaped IDs with individual receipt
reasons larger than 16 KiB, successfully accepts a result within the default
bound, verifies exact replay and remaining candidates, and starts a disjoint
followup only after cleanup. A maximum escaped-ID budget unit test proves the
complete projected result fits, not merely its raw input IDs.

Follow-up evidence (same bounded jobs setting):

- Root `cargo check`: **passed** (`fix-root-check.log`).

  **639 library + 11 binary passed**, no skips (`fix-server-full.log`).
